# AI 干活断片了？让它回来接着干

你让 AI 助手改代码、写功能、查问题。

它干了一会儿，窗口关了，电脑重启了，聊天太长了，或者你换了另一个工具。

再回来时，最烦的事情来了：

```text
它刚才做到哪了？
下一步要干什么？
有用的文件放哪了？
我是不是又要从头解释一遍？
```

Agent Watchtower 就是为这个烦恼做的。

## 一句话

它给 AI 助手准备一个本地工作记录本。

AI 做完一步，就把三件事写下来：

- 现在的目标是什么
- 下一步该干什么
- 已经做出来的文件在哪里

这样中断以后，再打开新的 AI 助手，它可以先看记录，再接着干。

## 它不是干什么的

它不是新的聊天机器人。

它不是替你自动完成所有项目。

它不是后台监控软件。

它也不需要登录账号、不需要连接云服务、不需要花钱调用模型。

它只是把 AI 工作过程中最容易丢的线索，放到你电脑本地的几个文件里。

## 普通人可以怎么理解

你可以把它理解成：

```text
给 AI 助手用的工作交接本。
```

人类干活时，如果今天没干完，可能会写一句：

```text
今天修到登录页面，问题在验证码，明天先看 api/login 这个接口。
```

Agent Watchtower 做的就是类似这件事。

只不过它用命令和本地文件，让 AI 助手也能留下这种交接记录。

## 你能看到什么

跑完最简单的本地演示以后，你会看到：

- 当前有没有任务可以继续
- 下一步建议做什么
- 上一次做出来的记录文件在哪里

那个“记录文件”就是 AI 这一步留下的结果说明。

它不一定是最终产品，也不一定是完整功能。

它的作用是告诉下一个 AI：

```text
我刚才做了什么，证据在哪，下一步从哪里开始。
```

## 快速跑通本地演示

安装以后，运行：

```bash
agent-watchtower init
agent-watchtower worker-status
agent-watchtower worker-run
agent-watchtower artifact-path
```

你不需要懂内部原理。

你只需要看最后一条命令输出的路径。

那个路径指向一个本地文件，里面写着这一步做了什么。

## 适合谁

适合经常遇到这些情况的人：

- AI 助手干到一半停了
- 新窗口不知道旧窗口做到哪了
- 换了 Codex、Claude Code、Hermes、CodeWhale 或其他编程 Agent 工具
- 项目做久了，聊天记录太长，恢复上下文很痛苦
- 想让 AI 每完成一小步都留下清楚记录

## 不适合谁

如果你只是和 AI 随便聊天，不做连续项目，可能暂时用不上。

如果你想要一个自动帮你赚钱、自动接管电脑、自动完成所有工作的系统，这也不是它。

它解决的是一个更小、更真实的问题：

```text
别让 AI 干活断片。
```

## 它会不会一直等我？

不会。

更准确地说，它会帮 AI 分清两种情况：

- 需要你做决定的事，要等你。
- 不需要你做决定、又安全的小事，可以先继续做。

比如 AI 问你：

```text
这个功能要不要上线？
```

这种需要你决定，它应该等你。

但如果它只是还可以继续整理文件、写测试记录、保存当前进度，就不应该一直傻等。

Agent Watchtower 的作用，就是让 AI 在继续做这些安全小事时，也把状态写清楚：

```text
我问了用户一个问题。
用户还没回复。
我先做了哪些安全工作。
下一步等用户回来后该看哪里。
```

这样你回来以后，不会发现它完全卡死，也不会发现它乱做决定。

## 给 AI 助手看的说明

普通人看这个页面就够了。

安装以后，真正给 AI 助手看的说明在：

```text
AGENTS.md
```

那里写的是 AI 应该怎么用这套命令：

- 开始前先看状态
- 有明确目标再加任务
- 做完一步就写记录
- 恢复时先找上一次的结果

人看介绍页，AI 看规则文件。

这就是 Agent Watchtower 的基本思路。
